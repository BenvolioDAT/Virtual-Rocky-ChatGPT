# ChatGPT Plus sign-in

Launch `launch-virtual.cmd`, click **Continue with ChatGPT**, sign in in the system browser, and authorize Rocky to use your ChatGPT plan. Return to the face window. No API key is needed for this option. ChatGPT plan eligibility, available models and usage are determined by OpenAI; this integration does not guarantee unlimited usage.

## Implementation

- Uses the [official open-source registration flow](https://developers.openai.com/siwc/token-sharing-open-source/sign-in), with a stable app host ID, dynamic first registration and the returned issued client ID for exchange/reauthorization. It does not use the Codex app's existing credentials or private ChatGPT backend endpoints.
- Opens a temporary HTTP callback on `127.0.0.1` and an available port; exact callback URI is preserved through exchange. No persistent server or LAN exposure. Callback request/response logging is suppressed. PKCE, state and nonce protect the authorization attempt; wrong-state requests are rejected without ending it.
- Verifies OpenAI's signed ID token against published JWKS, issuer, issued-client audience, expiry and nonce. Returning identity must match the selected registration. Identity sign-in without `chatgpt.tokens.use.direct` permission remains disabled for inference.
- Accounts/client mappings and tokens are saved atomically in ignored `server/.rocky-auth/accounts.dat`, encrypted with Windows DPAPI under the current Windows user. No tokens in `.env`, browser storage, logs or Git. Unix storage uses owner-only permissions. Copying encrypted credentials to another Windows user/machine is unsupported: sign in again there. Keep registration/host mappings after signing out, while clearing tokens.
- Refreshes shortly before expiry, writes rotating tokens together and serializes refreshes with a process lock. Sign-out attempts session revocation and clears local tokens; a failed remote revocation is reported with a route to disconnect the app in ChatGPT settings.
- Multiple account registrations remain separate even with the same email; UI shows stable labels and active selection. Switching clears local conversation history. Model choices come from the authenticated account's current catalog, preserving server order. Models and credentials stay bound to the selected registration.
- `ChatGPTBrain` reuses the original brain's personality, history trimming, camera hints, emotion-tag extraction and sentence limit. It converts existing history to [streaming Responses requests](https://developers.openai.com/siwc/token-sharing-open-source/models-and-inference) with `store=false`, `stream=true`, instructions and explicit history. Tools are grouped in a namespace. Camera/tool results are replayed. It drains the terminal event even after the spoken sentence cap, handling failed/incomplete/truncated streams rather than marking them successful.
- The [preview restrictions](https://developers.openai.com/siwc/token-sharing-open-source/preview-limitations) exclude speech input/output APIs from this sign-in route. Existing faster-whisper/Silero/Smart Turn and Windows/Fish speech remain separate and unchanged. Webcam images use models capable of image input.
- No automatic fallback to separately billed API usage. Existing provider configuration is available explicitly with `--provider api`. Original physical robot mode still uses its original provider path without importing the new JWT/Qt modules.
- Right-click: account/model choices, renewal, sign-out and Manage ChatGPT usage. The [Plus usage allowance is shared across participating apps](https://developers.openai.com/siwc/token-sharing-open-source/profiles-and-sessions). Sign-in grants no access to existing ChatGPT conversations.

## Verification

42 tests pass on Windows/Python 3.13, including original robot/virtual tests and new OAuth, signed-identity rejection, encrypted-storage roundtrip, login renewal, sign-out, account separation, real loopback callback with a fake browser/provider, UI login/cancel controls, Responses tool/vision replay and failure after the sentence limit. Credentials used in tests are fabricated and signed by a locally generated test key. Real OpenAI discovery metadata was fetched and matched the expected issuer and RS256 signing algorithm. Desktop runtime/sign-in-button render/shutdown passes with microphone and camera disabled. Python compilation, whitespace and dependency checks pass.

Live account authorization, model catalog and subscribed inference remain unverified until the user completes browser sign-in. No account access was requested on the user's behalf, no credentials were copied from other apps, and no ChatGPT plan inference was performed during implementation. Native mic/speaker/webcam acceptance remains as documented in virtual-validation.md. PyInstaller recipe remains unbuilt.
